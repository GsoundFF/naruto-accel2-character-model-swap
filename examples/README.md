# examples —— 完整实机验证过的替换记录

这些记录来自真实做过的 MOD，每一份都包含：角色代码怎么确认的、三个变体各自的骨架与索引、
映射表怎么算的、踩了什么坑、产物是哪几个 span、以及全盘比对结果。
配合 `../SKILL.md` 阅读效果最好。

方向命名规则：`record_<目标>_from_<来源>.txt`
（目标 = 保留自己动作、被换外观的角色；来源 = 提供外观的角色）。

| 文件 | 方向 | 说明 |
|---|---|---|
| `record_INW_from_SZW.txt` | 井野 ← 静音 | 最早的完整流程；含**奥义**修复全过程（先换 MODEL 无效 → 改用 1P 才生效），以及 1P 眼嘴件 parent 写错导致卡死的教训 |
| `record_SKR_from_TEN.txt` | 小樱(SKR) ← 天天(TEN) | 两骨架 0-23 同名 ⇒ 战斗/MODEL 的 lookup 恒等；CLUT 数量不等时复用 tint |
| `record_SKW_from_TEW.txt` | 小樱(SKW) ← 天天(TEW) | 骨架位置不对齐，必须按名字映射；并给出"基于已验证战斗版补奥义"的打包方式 |
| `record_SKW_from_SZW.txt` | 小樱(SKW) ← 静音(SZW) | 索引高度对齐、最省事的一例 |
| `record_KRW_from_SZW.txt` | 夕日红 ← 静音 | 1P 左右骨骼同名 ⇒ 必须 occurrence-aware 映射；含**方向搞反**与**容量不足**两个坑的完整记录 |

## 从这些记录里能提炼出的通用结论

- **奥义读的是 `1XXXBOD1`（1P 高模）**，`MODEL/2XXXBOD1` 经常无效；
  奥义 cut-in（`/CUTIN/`）只有动画+相机，复用 1P 模型，所以不用单独改。
- **方向决定成败**：源模型比目标小才塞得进原位补丁。
- **骨架对齐情况每次都要重新确认**：即使是同一对角色，战斗/MODEL/1P 三套的骨数和对齐度都可能不同。
- 每步都要用 `readCCS` 重解析自检（块顺序、meshCount、lookup、材质、贴图 clut），
  最后再做一次全盘比对。
